# Disposable Android emulator integration

This is a separate engineering test, not a store build, private-user APK, Play Protect verdict or physical-device proof. It never disables Android's install protection or changes a personal device. The production source keeps its normal network/security manifest.

## Scope and safeguards

The standard `ubuntu-latest` public CI runner boots separate Android34 and Android36 Google APIs x86_64 emulators for the target36 candidate using KVM. It builds current Go bindings and the actual app from a fresh source archive. Only the throwaway copy is marked debuggable and allowed cleartext loopback, for its local control-plane fixture. It uses a disposable debug signer, not an upload/release credential. No test APK is retained as an artifact or sent to a user.

A real Go userspace mesh peer serves a bidirectional4MiB SHA256 protocol on its mesh IP, not on the host network. Instrumentation launches actual MainActivity, fills only fixture credentials, clicks the OS VPN consent dialog in the fresh emulator, waits for actual Node up, verifies both payload directions, manually stops and reconnects after the worker exits, then verifies both directions again. The corrected fixture keeps that instrumentation alive while a separately installed app UID performs unbound TCP transfers twice, then stops manually. The separate UID has INTERNET permission but no access to the production Node API. Passing only the self-bound phase is not a full fixture pass. It does not mock the Go node or Android VPN interface.

Expected outputs are explicit PASS summary and a pre-credential launch screenshot. The public artifact allowlist contains only summary.json, instrumentation.txt, launch.png, privacy.png, vpn-disclosure.png, consent.png and consent.mp4. The MP4 is a sampled screenshot walkthrough of disposable hosting/settings/system-consent screens, not uninterrupted video. Capture stops and the sampler joins before returning to credential-bearing MainActivity. consent.png is captured only on controlled hosting/projection consent failure screens. State, enrollment keys, APKs, raw instrumentation output and logcat are not uploaded. Fixture control listens on loopback, Android reaches it via adb reverse, and temporary fixture files/processes are removed. No existing service/network/account is touched, and no paid/larger runner is selected.

## Limits and next stages

- Actual remote capture/input and system accessibility enablement are now exercised. Network-radio loss, reboot/unlock/always-on, physical/OEM and long-session soak remain open.
- A real peer plus emulator is not two physical phones, a public-internet test or a manufacturer battery-policy test.
- Google APIs engineering images and adb instrumentation do not test the Google Play installation/approval path. The private-user APK's Play Protect block remains a separate issue.
- A stage that times out/fails is a failure to diagnose, never partial evidence of an end-to-end pass. No release or physical-phone retry follows automatically.
