# Private native-owner pending-intent composition

No production caller or exported setup API is added. New private prepareNativeEnrollment composes the retained actual native State owner/current policy capture with the disconnected durable journal and fresh owned loopback socket. Daemon.New/Up, local HTTP APIs, mobile and browser do not trigger it. Policy installation and account enrollment remain off.

Under d.mu, preparation first validates the existing durable native key and fixed strict current policy. It converts the SAME public-key bytes from native State standard base64 to source canonical raw base64url, never accepting an arbitrary caller key. It opens only the fixed enrollment-pending subdirectory of the retained native owner's canonical directory. It saves full original policy and fresh socket launch through PrepareCheckedCallback. It revalidates actual State/policy before returning launch DATA and installs only a private in-memory lifecycle handle. Existing intent or any failure is never reset/cleared or renewed; saved intent on later failure stays suspended for explicit recovery.

Callback admission additionally revalidates the original context against the same retained native owner, actual current policy and actual saved native State. The callback admission hook is an optional DATA-layer caller check, not a source/principal authentication or authority grant. It runs outside the journal mutex to avoid reversing the native/journal lock order. There is no atomic promise against adversarial same-UID edits between a point-in-time policy check and callback DATA publication. This is not credential finalization and no authority follows from callback DATA.

Daemon.Close marks closed, disposes any private journal/socket and cancels journal I/O before native teardown/releasing the retained native owner. No enrollment preparation is automatically reconstructed on restart. The old saved intent blocks fresh preparation; explicit old-intent recovery remains unimplemented.

Actual local tests exercise owned key bytes and complete policy pinned in journal, exact socket callback success, no State/policy/node/client/device mutation, duplicate preparation refusal, absent/malformed policy or missing actual key, explicit oversized lifetime refusal, changed current policy/State and owner fault refusing callback, Close socket/journal disposal, and actual daemon restart refusing automatic renewal. Deadline rejection can create only the dedicated private directory/lock, never an intent/key; policy validation occurs before that directory is opened.

Remaining gaps: policy installer/authority, browser/first-run UX, trusted external time/eligibility, registrar bootstrap/challenge/verified proof, durable outcome recovery and actual atomic native-State/journal credential finalization. Private preparation is not a permit, node credential write, tunnel grant, screen/input grant or real Multies-to-native end-to-end acceptance. Native OS checks are compile-only; native Windows/macOS/mobile execution and downgrade discipline are separate.
