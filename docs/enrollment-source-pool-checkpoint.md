# Disconnected bounded service-source transport pool

No production consumer or actual installed policy/Store authority is added. NewPool accepts a finite explicit config DATA list and engineering limits. It constructs/owns its own existing strict service HTTP clients, not caller-supplied clients/transports. Config/mappings are defensive. It owns only HTTP cancellation and admission resources, never eligibility, a challenge, permit, Store node/receipt or native credential.

Explicit required bounds: maximum configured sources, concurrent global calls, concurrent per-source calls, and total admitted original attempts during this pool lifetime. Engineering ceilings are32 sources,256 concurrent calls and100000 attempt records, not product defaults or an authorization lease. Config must have unique local aliases AND unique exact source origins. Another alias/key/service for the same origin cannot multiply a source's concurrency budget. Dynamic rotation and multiple independently scoped services at one source are deliberately unsupported pending an actual policy owner.

Before private HTTP, under one mutex: cheap strict descriptor/mapping validation; resolve only configured local source alias; check permanent attempt/capacity/global/per-source limits; spend one attempt slot and reserve concurrency. No remote send or DH can precede this. Original attempt key is SHA256 of exact JSON tuple configured source origin, configured principal authority, launch attemptId. Raw secret/ticket is never a map key. The digest is an in-memory cardinality key, not authentication. SHA256 collision can at worst cause conservative refusal, never grant access.

At most one attempted send per qualified original attempt. Changing reserve ID/descriptor/key/alias cannot renew it. Success, network loss, invalid response, cancellation or even a local failure after admission never refunds the slot. There is NO automatic retry, live eviction, expiry GC, source reserve reconciliation or reset method. Pre-admission concurrency refusal spends no new slot. Full permanent capacity refuses new work. Total memory is bounded by explicit attempt count; this is not an unauthenticated ingress rate limiter or a production retention policy.

Close is idempotent/copy-safe, refuses new work and cancels admitted I/O before discarding any result. Caller cancellation also returns remote-unknown after admission, with slot retained. In-flight count is released only after client return; Close does not claim to synchronously wait for all handlers. A successful returned object is strict observed source DATA only. Pool restart/reconstruction loses its in-memory admission history; no cross-restart dedup/unknown recovery is claimed. Durable source reserve-ID dedup is distinct and not replaced by this helper.

Actual local TLS tests cover global and per-source admission independently, zero HTTP on refusal, pre-admission refusal not burning an attempt, one-send after loss, changed reserve on same attempt before capacity exhaustion, permanent capacity, Close/caller cancellation reaching actual handler, copied lifecycle, config alias defenses/defensive mappings/invalid config, generic output and strict successful DATA with no renewal. An initial cancellation test blocked because the test server didn't drain request body before waiting for disconnect; corrected test drains it and bounds its wait. This was a test harness issue, not evidence of production source cancellation failure. Final passing logs are separate from that initial diagnostic failure.

Actual registrar/Store owner/current service policy, secret provisioning/rotation, source time/lease rules, ingress/global abuse budgets, authenticated attempt authority, persistent outcome recovery, challenge ownership and atomic consumed-proof/node/receipt finalization remain open. No service credentials, live accounts, source requests outside disposable tests, activation, push or deployment occur.

## Canonical source-budget config correction

Independent review correctly identified that exact-string origins alone allow hostname-case/default-port aliases to multiply per-source capacity. Pool config now rejects noncanonical source spellings rather than rewriting exact protocol identities: lowercase ASCII DNS labels (punycode explicit), no terminal dot, canonical nondefault port decimal spelling, canonical netip IPv4/IPv6 spelling with no zone or IPv4-mapped alias, no ambiguous numeric-host form. Explicit443 is rejected for this pool, not globally reinterpreted as another identity. Existing descriptor/origin contract bytes are unchanged. No migration or config rewrite is performed. Canonical accepted strings remain exact on wire.

This does not detect DNS aliases/CNAMEs or multiple hostnames backed by one service. Such separately configured names remain separate per-source scopes under the single global ceiling; no DNS lookup, IP-based authority inference or claim of per-physical-service enforcement is made. Principal/registrar protocol identities outside source-budget admission remain exact configured contract strings.
