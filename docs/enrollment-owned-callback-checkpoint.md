# Disconnected owned IPv4 callback transport

PrepareCallback explicitly reserves a fresh tcp4 127.0.0.1:0 socket BEFORE the journal pins/returns its exact literal callback URI. It supplies that address to the existing Begin durable-intent operation, with caller-provided public key, inactive LocalPolicyV2 snapshot, clock and expiry. It does not establish actual key ownership or installed/current policy authority. There is no daemon consumer, browser opener, source exchange, registrar request or enrollment activation.

The journal lifetime owns the callback. Value copies share lifecycle. A failed save or post-save lifecycle/time check returns no launch and closes the socket. Any already-saved intent is preserved for explicit recovery. Existing intent is never replaced. A callback cannot reconstruct a socket after restart or accept an old late response after explicit listener Close. Closing a socket does not fabricate decline/approval or clear saved recovery data.

The HTTP handler accepts only exact IPv4 loopback peer, GET, exact bound literal Host, exact unescaped path, non-absolute request target, no Origin, no request body/transfer encoding, bounded query with exactly three distinct single-valued fields, exact state/attempt and canonical code OR literal access_denied error. This matches the actual Multies service redirect field names. Invalid requests do not consume/retire a valid intent. No CORS, redirect or request-derived body text is returned. Responses have no-store/no-referrer/CSP/nosniff headers and explicitly do not claim network/screen/input access.

Success first durably records callback code DATA, then retires the socket and returns generic plain text. Matched decline first durably records a new declined-data phase, then retires/responds. Decline is DATA from the correlated callback, not authenticated source/principal authority. Record schema remains experimental v2; older code that does not understand this new phase refuses it rather than silently recovering.

Expiry is explicit with a 15-minute upper bound, no default. Admission/expiry uses caller clock bounded by actual elapsed time; the actual socket deadline consumes save/setup time as well. It is not a trusted remote clock or source-eligibility proof. Header/body/write/idle timeouts and an eight-accepted-socket budget bound local listener resources. No source request or automatic retry is triggered. Journal Close closes the socket/server; successful response allows bounded graceful drain. A callback already admitted before Close may have durable DATA even if its HTTP response is lost; no account effect follows from DATA.

Real local-socket tests cover durable allow/decline and reopen, method/host/origin/path/encoding/duplicate/extra/bad state/attempt/code/error rejection, save failure, existing-intent refusal, copied lifecycle/explicit close, actual deadline and ninth-idle-connection rejection. Existing file/fault/concurrency/source-client tests remain. These are transport and persistence tests, not real browser navigation, inspected setup UI, native Windows/macOS/mobile execution, actual Multies-to-native E2E or authority-finalization acceptance. The response is plain text; no designed browser UI or visual acceptance is claimed.
