## Bounded instrumentation

The prototype verifier keeps its exact Chrome launch arguments, fresh temporary profile, descriptor 3/4 NUL-delimited JSON transport, 15-second command timeout and all 84 screen/width assertions. New telemetry records only fixed fields: spawn observed; write attempts, successful callbacks and errors; receive-byte count; first-response timing bucket; pipe end/close; numeric browser/Node versions; platform/architecture; and a fixed child-state category. Counters saturate. It never retains or publishes transport payloads, raw stderr, environment, machine/profile paths or page/private content.

Browser version is queried only when reporting a completed verification or an already-expired command, with a separate bounded version-query timeout. It does not delay startup before the command. Version output is accepted only as a known product line followed by numeric version components; other output becomes unavailable. Process state reads return only a fixed category, not process names or paths.

Unit checks cover sanitization, silent/ended/closed states, version rejection, timing buckets and actual inherited descriptors delivering a response before peer closure. An isolated silent-child fixture drives the full verifier's unchanged timeout: it reports one successful write callback, zero received bytes and no first response, without disclosing a synthetic private stderr marker. This validates the evidence path, not a reproduction of Chrome's underlying failure mechanism. Three unchanged local prototype journeys and four instrumented journeys each passed 84 checks. Local Node 22.23.4 matches the failed runner's recorded Node version; local Ubuntu 22.04.5 differs from runner Ubuntu 26.04.1/image20261111.82.6. The failed logs did not record browser version, so that difference is unresolved.

This checkpoint is instrumentation, not a proven root-cause correction, timeout increase, product change, acceptance of the prior failed run or a guarantee of future startup. Fresh normal CI and deployed verification are pending. Workflow permissions/settings/triggers are unchanged; no native/release, live account/device, production service or paid-resource expansion is made.
