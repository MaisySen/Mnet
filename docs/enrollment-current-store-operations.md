# Private current-credential Store operations, same-lock checkpoint

The existing-record verifier is now composable with actual map snapshot and endpoint persistence under the SAME actual retained Store.mu. New private registrarCredentialMap/setRegistrarCredentialEndpoints are uncalled and have no registered routes, native consumer, credential parser or installer. They consume an existing strict v2 record/reference plus matching native secret, never create a node, credential, receipt or consumed proof. This is current-access composition, not enrollment authority.

## Atomic local access boundary

The existing verifier body is extracted into authorizeRegistrarCredentialLocked, requiring actual Store.mu. Existing authorizeRegistrarCredential still takes the same lock and returns detached node DATA. The new wrappers hold Store.mu across verification and actual map snapshot/endpoint update. They never use a prior successful node clone as permission to perform a later unlocked operation. ExpireNode/DeleteNode/Close serialize on that same mutex. A call admitted before revocation can complete first; every operation started after transition completion refuses. Holding a mutex does not stop wall time or promise a continuous network lease. Snapshot publication/HTTP encoding later also needs its own lifecycle design; no exposed consumer exists.

Map snapshot extraction into mapSnapshotLocked preserves legacy owner/current access/network/peer cloning checks. finishMapSnapshot applies existing ACL filtering and sorting to detached values after owner unlock. Actual legacy Map uses these same helpers with unchanged ordering/semantics. New credential map validates exact SAME record/secret before snapshot. It returns no credential-bearing relay URL. A map snapshot cannot authorize WebSocket relay use or continuous packet delivery. Relay attachment/current revalidation remains unimplemented for this credential.

SetEndpoints extraction into setEndpointsLocked preserves existing filtering/sort/dedup/no-op/version/publication semantics. Existing public legacy SetEndpoints continues its old behavior; it is NOT silently changed into credential verifier. New private registrar wrapper verifies current record/reference/secret before entering that body under same owner lock. Actual Store publication has rollback-safe failure or uncertainty freeze; no fake durable success. Existing no-op behavior updates in-memory LastSeen without write/version and remains unchanged. Network endpoint reports are not a new lifetime grant or enrollment mutation.

## Evidence

Tests use actual strict test-owned v2 record/secret save/Close/reopen. Actual endpoint update deduplicates/publishes version, map returns detached key/expiry/endpoints/network, no-op avoids disk/version, owning reopen retains exact published endpoints. Wrong secret/qualified scope/revoked/deleted refuses both operations without bytes/version/data effects. Actual ACL test joins/approves two ordinary peers plus isolated-network peer; only allowed same-network peer appears, and mutated returned ACL/peer cannot alter owner. An initial fixture incorrectly reused one network's auth key across another network and correctly failed; final test uses ordinary pending Join plus explicit test-owned approval for peers, never modifies key scope.

Actual endpoint persistence fault matrix covers temp create/write/short write/file sync/close/rename, post-rename failure and parent sync. Prepublication failures restore whole live/disk image and exact current retry works. Postpublication uncertainty freezes same-owner credential map/update, no successful version bump, owning reopen reads complete candidate. Eight concurrent map/update readers race actual ExpireNode/DeleteNode/Close;30 subsequent map/update checks per transition refuse. Legacy full suite/snapshot/endpoint/ACL behavior runs through shared helpers, not separate copied production implementations.

Full Store validation is still O(history) per request and no production ingress bounds/caching/benchmark claim is added. No continuous watcher/current lease, timer or irreversible commitment is inferred. There is no handler/parser/network request in this checkpoint, so no bootstrap/current-control scheme is wired. A future separately reviewed consumer must not chain legacy nodeAuth to these APIs or expose raw native secret through query/logs, and must bind current receipt/epoch and packet/relay lifecycle independently.
