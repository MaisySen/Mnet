# Private native-owned source exchange composition

New private exchangeNativeEnrollment has no production caller. It composes only this daemon's existing private preparation with the journal one-shot source adapter. It validates the same retained native owner, already-durable key, original State revision and exact current policy before admission. Every original/current callback from the adapter reacquires d.mu and repeats those actual checks. Network I/O never holds d.mu; actual time.Now and explicit source transport limits are used. Closing the daemon disposes the journal, cancelling admitted I/O while preserving durable remote uncertainty.

No browser or source request happens at startup, prepare, Up, callback receipt, mobile or any existing HTTP route. Source exchange requires an explicit invocation of this otherwise-unused private method. It returns forgeable strict source DATA only; it neither constructs a permit nor writes node credentials, control client, network configuration or native State. A successful own-PKCE exchange is not registrar finalization or device enrollment.

Actual local-TLS test cases use the real native owner/current policy file, actual saved journal, actual loopback callback, actual default verified source client and a disposable certificate added to test process roots. No production TLS bypass, custom transport or secret getter is added. The server checks the exact previously saved own launch/code/verifier and durable may-have-started phase before source send. Cases cover success and durable exchanged DATA, pre-I/O policy/State change with zero sends, in-flight current policy/working State change, lost response, and daemon Close during I/O. A second invocation cannot repeat admitted one-shot exchange. Native State bytes remain unchanged and no node/client/device is installed.

This is not actual Multies-to-native E2E: the local TLS source is a test handler returning a constructed strict response. Real Multies producer/parser parity is established in separate source fixtures, not by this integration test. There is no trusted external time/eligibility proof, registrar admission policy, bootstrap challenge, MAC confirmation, durable recovery/atomic finalization, installer or first-run UX. Current-policy authority still depends on the future authorized installer; the fixed file and checked context do not create that authority. Native OS checks are compile-only.
