# Inactive strict experimental-v4 wire DATA

New explicit version4 transport envelopes are a disconnected proposal, not a live protocol or silent upgrade. Challenge envelope has version/challenge with exactly the existing Challenge/Binding fields. Response has version/challenge_id/response_mac. Confirmation has version/challenge_id/confirmation_mac. The latter two carry no binding or caller-selected reference resolver. Existing v4 binary transcript is unchanged. No v2/v3 fallback.

Decoders bound input to16384bytes, require valid UTF8, exact recursive field names/required/non-null members, refuse duplicate/unknown/case aliases/trailing values and require literal integral signed64 numeric spelling via json.Number.Int64. Challenge invokes existing transcript Encode for semantic DATA validation. IDs/MAC strings require existing canonical nonzero32-byte base64url grammar. All outputs remain public mutable untrusted DATA. Redacted formatters avoid accidental private transcript/MAC log output.

A parsed Challenge is NOT an independent expected Binding. A parsed response MAC is NOT possession verification. A parsed confirmation is NOT authenticated registrar identity, durable commit or current network access. No crypto calls, durable native key bridge, bootstrap scheme/header parser, HTTP route, source/client request, proof permit or Store/native writer is added. A real consumer must independently own authenticated exact channel, outstanding challenge, expected binding, clock/lease and durable outcomes; passing these DATA structs to crypto without that remains wrong.

Tests cover exact roundtrip, purpose-disjoint schemas, every nested field missing/null/case substitution, duplicates/unknown/trailing/version aliases, overflow/fraction/exponent/wrong-type timestamps, malformed/oversize/invalidUTF8, canonical ID/MAC and redacted formatting. Fuzz exercises all decoders. This is syntactic/contract acceptance only, not a security review of transport design or any deployed/native OS flow.
