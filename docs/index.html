Mnet Android privacy policy

Effective 17 November 2026. This policy covers the Mnet Android internal-development test, not a public production service or a future Multies integration.

Mnet connects approved devices on a private mesh network. Screen sharing and remote gestures are optional. Share only with devices and people you trust. An approved viewer can see sensitive information on your screen and can make copies.

Who operates Mnet

Fintex Australia Pty Ltd operates Mnet. For privacy, support or data-deletion requests, email contact@fintex.au. The operator monitors this inbox. Do not send passwords, enrollment keys or private node keys.

Information on your phone

Mnet saves your control-server address, network name, enrollment key and device name in app-private settings. It saves a device identity, including private node keys and join credentials, in app-private files. These let the device reconnect to its approved network. Private node keys are kept on the device; public keys and enrollment information are used to register it.

Disconnecting does not delete these settings or credentials. Removing app storage through Android's app settings removes local app data. The current app disables Android backup and declares cloud/device-transfer exclusions. This is not a guarantee about earlier backups or every manufacturer's transfer tools.

Connection information and DNS

The configured Mnet control service processes device names, network membership, public keys, enrollment credentials, assigned and connection IP addresses, endpoints and approval status. Devices receive network information needed to reach approved peers. Operational audit records can include event time, event type, client IP address, actor, event detail and outcome.

For NAT discovery, the app sends STUN binding requests to Google and Cloudflare public STUN servers. These providers see the connecting IP address, port and request metadata. The binding requests do not contain screen images or chat content.

Mnet configures a DNS resolver for the VPN connection. Names in the .mnet zone are answered from the mesh network map. Other DNS queries are forwarded to the system-configured upstream resolver where available, or to Cloudflare's 1.1.1.1 resolver as a fallback. That resolver can receive queried domain names and connection metadata, including queries made by other apps using the VPN's DNS configuration. DNS forwarding is not a promise that all of your internet traffic uses the mesh or is hidden from your internet provider.

Screen sharing and remote gestures

Screen capture starts only after you start hosting and accept Android's separate screen-capture permission. A viewer must be approved unless you explicitly enable automatic acceptance for that hosting run. Screen images are sent to the connected viewer.

Optional accessibility access lets an approved viewer send supported taps and scrolling gestures while you host. Mnet is not an accessibility tool for people with disabilities. Its accessibility service does not read window text or contents, receive accessibility events, or type text. Screen images use Android MediaProjection separately.

You can decline the accessibility disclosure and stay in Mnet. VPN, viewing and screen-sharing paths do not require accessibility access, but remote gestures do. You can stop hosting and turn off Mnet in Android Accessibility Settings.

Messages, files and recipients

Session messages and file-transfer code process content sent between endpoints. Android file saving is not a verified supported feature in this test; do not rely on it for document storage. Other platforms can have different recording and storage features.

WireGuard encrypts mesh payloads between endpoints. The configured control/relay infrastructure can still process connection metadata and relay encrypted traffic. Encryption does not hide content from the endpoint you share it with or protect a compromised device. Another endpoint can retain received content, screenshots or recordings.

The current test control/relay service is hosted by Render in Singapore on a free instance without a persistent disk. This test does not enable the optional identity-provider login configuration. The app has no advertising integration or intentional analytics event collection in its current runtime paths. Necessary operational/audit data and third-party connection/DNS handling still occur as described above.

Retention and deletion

  • Local configuration and identity: remain until app data is removed or explicitly changed. Disconnecting is not deletion.
  • In-memory session state: the Android host keeps the latest encoded screen frame in memory; stopping hosting ends projection and drops that reference. Displayed viewer/chat state is held in memory. This does not guarantee erasure of platform buffers or another endpoint's copies.
  • Control state and application audit records: the current test has no automatic age-based deletion schedule. Records can remain until removed by the operator or lost when the ephemeral host restarts, redeploys or spins down. This host behavior is not a complete privacy-deletion process.
  • Provider records: Render, Google, Cloudflare and an upstream DNS provider can keep their own operational records under their applicable policies. Mnet does not set or promise a fixed deletion period for those records. Render runtime-log retention depends on the workspace plan. Removal of a Mnet node does not erase provider logs.
  • Support requests: email and handling records can remain in the support mailbox until manually removed; no automatic deletion schedule or fixed response deadline is offered for this internal test.

To request deletion, email contact@fintex.au and describe the device/network or records concerned without including secrets. Requests are handled manually. The operator may need to verify your authority and clarify the affected records before changing access or deleting data. A device-name match alone is not sufficient verification.

Removing an exact node can remove its control record and revoke access, but it creates an audit event and is not a purge of every related audit, membership, provider or support record. This test has no one-click all-data erasure or self-service account-creation flow. The operator will need to identify which records can be removed and explain any records that remain, including records retained for security or legal reasons. No guarantee is made about copies held by session recipients or providers.

Your choices

You can disconnect the VPN, stop hosting, refuse a viewer, decline accessibility access, disable that access in Android Settings, remove local app storage, or stop using the test. Avoid sharing sensitive screens and content. These controls do not themselves submit a server-side deletion request.

Changes and contact

This policy will be updated if this test's data handling changes. A public release, added testers, identity-provider login, recording features or Multies integration require a fresh review rather than an assumption that this restricted test covers them. Contact contact@fintex.au with questions.
