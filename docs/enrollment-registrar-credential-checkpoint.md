# Private existing-record registrar credential verifier

New private authorizeRegistrarCredential has no production caller/route, no selected HTTP scheme/parser, no exported authority constructor and no node/receipt writer. It can only check an EXISTING strict Store v2 consumed-proof record and return a detached current node snapshot. Test-only fixture records are not a production path to create verified history. This does not implement enrollment or finalization.

Under actual Store.mu/retained owner health, verifier requires canonical nonzero32-byte unpadded base64url secret text, v2 namespace/receipt plus consumed proof, complete exact caller reference matching SAME owned record: node/network/raw-key, full issuer/origin/audience/service/workspace/revision/handoff/attempt/reserve scope, receipt ID/digest, descriptor digest and consumed transcript digest. It validates actual namespace/index/receipt/consumption and refuses mixed legacy/account identity or route/exit capabilities. Caller reference is DATA, not expected provenance or a grant.

SHA256 of canonical43ASCII secret TEXT is compared constant-time against SAME stored record credential digest. This preserves actual Multies text-hash semantics; decoded raw bytes, public digest itself and legacy token equality are not alternatives. Shape/scope/existence checks are not constant-time and this is not a promise of endpoint enumeration resistance. An eventual ingress needs its own strict generic bounded authentication/admission behavior before expensive Store validation. No Authorization scheme is silently chosen here.

Current node must exist in the actual network with exact ID/key, approved, exact record access expiry, committed time not in future and access not expired. Revoked/deleted/closed/frozen/released owners refuse. Returned clone is point-in-time only, not a continuous access lease; eventual map/relay consumers must recheck their actual lifecycle/current state. No proof or receipt is consumed, no access extended, no secret stored or native State changed. Existing legacy AuthorizeNode still refuses all registrar nodes even with matching native secret.

Tests use actual strict v2 test-owned Store setup/save/Close/reopen. Cover canonical correct secret, wrong secret/public digest/padding, every qualified reference/scope field, current revocation/expiry/missing node/network/unapproved/mixed token/route/exit/user corruption, receipt/proof/index corruption, legacy-v1 namespace, closed/faulted/released owner, detached output and unchanged disk/version/data on reads/refusal. This is verifier mechanics acceptance, not evidence that fixture history came from a real authenticated commit.

Full namespace revalidation is O(total retained history) on every call. Production scale/ingress caching and time/retention policy need separate review before exposing it; skipping validation or treating a cached node as authority is not a fix. Native credential schema/client, authenticated bootstrap and receipt wire, actual atomic consumed-proof/node transaction, trusted lease/revocation policy, installer/UX and physical/native OS acceptance remain open. No source/network/account effect or deployment occurs.
