# Visible Android End viewing action

The viewer now has a visible End viewing button instead of relying only on system Back. It uses the existing terminal owned-viewer teardown: stop reconnect, invalidate the current gate, close the published session, clear decoded frame and touch dimensions, disable input and finish the Activity. Activity destruction shares the same idempotent cleanup.

The handler removes only the retry task, not every queued message. A pending connect result must still reach its rejected-publication callback so its returned handle can close. Late frame/control/closed callbacks cannot restore the ended gate or schedule reconnect. A gesture or write already dispatched may complete. The original button-only revision could not interrupt a blocking connect. The follow-up adds a single-use SessionConnect handle: End cancels its dial context and closes its pending hello socket without shutting down the mesh, another pending attempt or another active viewer. The handle belongs to the current ViewerGate ticket. A successful connect transfers socket ownership to the returned viewer; cancellation after that transfer is a no-op on the attempt, so rejected late publication must still close the viewer. The application initiates cancellation immediately, but this does not promise a particular native OS callback/teardown latency. Already-dispatched input is not recalled.

They cover cancel-before-start, idempotence/single use, owner temporary/permanent stop, context cancellation with a controlled pending-dial waiter plus the real source-bound DialContext on an already-canceled context, cancel during a real protocol hello over net.Pipe, a socket arriving after cancellation, an active sibling surviving cancellation, transfer to the caller, and closing a returned viewer canceled before publication. The controlled dial waiter is a cancellation-contract check, not a real Android in-flight TCP syscall measurement. Protocol/ownership tests use loopback pipes, not encrypted mesh routing. The framework pending-connect test now also checks that End calls its fake native attempt's Cancel immediately; its fake worker intentionally ignores cancellation until released, exercising late cleanup too.
