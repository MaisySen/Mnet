# Inactive native credential schema and actual-owner candidate

This checkpoint follows current strict-loader refusal tests. It implements a separate explicit document schema, a shared Store receipt-v2 byte codec and a private actual-native-owner candidate checker. No State.json fields, files, startup consumer, credential writer, request scheme, controlclient fallback, route, installer or finalization transaction is added. A document that passes these checks is internally consistent DATA, never an authenticated historical receipt, permit or usable node credential.

## Schema and parser

NativeCredentialDocument version1/kind registrar-native-experimental-v1 contains secret, finalization_id, full v4 challenge, full qualified receipt-v2 projection and receipt_digest. All fields required, exact names, recursive duplicate/unknown/case/null refusal, literal int64 integer numbers, valid raw UTF8 and total16KiB cap. It uses the existing reviewed strict wire grammar. Whitespace is accepted; Go JSON surrogate-to-replacement semantics remain. Do not reconstruct authenticated input bytes from parsed structs or treat ordinary JSON marshal as canonical authenticated wire.

The new native secret must be canonical unpadded nonzero32-byte base64url. SHA256(secret TEXT) must equal the SAME challenge/receipt credential digest, constant-time digest comparison; decoded secret bytes or public digest equality are not alternatives. Every receipt field must equal the exact challenge-derived projection, except syntactically bounded node/receipt identifiers and commit time. Commit must be no earlier than checked-at, earlier than challenge expiry and access-until. Access expiry remains exact challenge value. No now, default lifetime or lease extension is chosen. An expired historical fixture deliberately parses; syntactic validity is not current access. Finalization ID is canonical nonzero32-byte DATA, not an idempotency transaction or actual pending marker.

The receipt uses existing Store standard-base64 device key bytes, while the challenge uses canonical rawurl key. Exact raw key bytes bridge them, never text normalization. Receipt scope includes issuer/origin/audience/service/workspace/revision/handoff/attempt/reserve/descriptor, node/network/key/credential, receipt ID, commit/access times and consumed challenge/transcript digest.

## Shared historical receipt bytes

ReceiptV2Bytes exactly reproduces existing private Store v2 length-prefix recipe. This raw byte function intentionally validates nothing, including descriptor version. Actual existing Store namespace validators remain responsible for historical compatibility. Store v2 serializer delegates only the populated v2-consumption case; v1 and malformed missing-consumption byte behavior stay unchanged. A frozen pre-extraction independent test reproduces old bytes with unusual Unicode/control/space strings, negative times and wrong descriptor version to prove extraction itself adds no validation/normalization. Independent Python fixture rebuilds v4 transcript and665-byte receipt, including Unicode/HTML vector values. Go byte equality and full document equality pass. Nothing authenticates those test-created receipts.

## Actual owner-bound candidate

Private daemon prepareCredentialCandidateLocked reads only caller-supplied raw document, captures actual retained own State/key and exact current installed local policy through existing owned context, then checks document consistency, same actual key, original explicit principal namespace/authority/service/mapping eligibility. It revalidates actual current context on every check and refuses foreign owner, changed policy/key/principal/document, Close, legacy node/token/authkey and routing/exit capability. There is no filesystem loader or secret getter, and no production caller consumes the candidate. Candidate String/GoString redact the document. Tests use actual durable State/policy owners and verify no file/State change or alternate credential location. The old strict State loader continues rejecting unknown future markers; it has not been taught to install this schema.

A fully self-consistent attacker-created node/receipt/digest can pass the syntax checker. Tests explicitly demonstrate that to prevent authority laundering. Matching the owner's key/policy only adds local consistency, not source eligibility, receipt provenance or proof consumption. Another same-package caller could also construct DATA; no authority derives from that pointer. Future authority must come from independently authenticated exact registrar delivery and actual commit history, not these constructors.

## Remaining functional target

Separate dedicated current-control transport/client, authenticated bootstrap and immutable receipt/history wire are still needed. Native State versioned usable-credential storage must be explicit and exclude legacy token/AuthKey fields; installer/version floor and actual old-binary rollback acceptance remain unresolved. Atomic registrar consumed-proof/node/receipt producer and native two-file finalization/recovery are still missing, including one usable secret location, policy/clock/revocation decisions and crash outcomes. These prerequisites cannot be replaced by digest matches, DH confirmation, source DATA or current-schema syntax. Current no-route/default-off/isolation/release restrictions remain.
