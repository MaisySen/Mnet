# Headless session-host process ownership

The daemon previously launched its session-host goroutine without a shutdown owner. Its mesh-ready wait, listener Accept, accepted hello socket and active session sockets could outlive runDaemon when invoked as an in-process service. The main run teardown also used reusable Down, leaving a not-yet-entered startup goroutine able to begin after that boundary. No live service incident or physical capture teardown is claimed from this source finding.

The process lifetime now permanently Closes the daemon on every return, including setup/self-test/error paths. Local API Down remains the separate reusable operation. The host has a per-run owner: initial mesh-ready wait observes cancellation, listener attachment and accepted-socket adoption refuse a closed owner, and shutdown closes the listener plus every pending/active accepted socket. A socket arriving during shutdown is closed instead of escaping ownership. Each wrapped socket removes itself once on Close. The accept loop returns on owner cancellation rather than logging/retrying a closed listener forever. Main waits for that listener/readiness loop to exit before releasing the process state lock.

Closing transport causes existing per-session cleanup to stop Host workers and close recorder/capture/input resources. This does not forcibly interrupt an arbitrary blocking platform capturer/injector constructor or user callback. Main does not wait indefinitely for every such external callback; its joined guarantee is the host accept/readiness loop and owned transports, not a hard capture-resource latency. Already-dispatched work can finish. Peer authorization, headless opt-in/allow-list, combined admission and desktop file/recording policy are unchanged; no new unattended-control grant is added.
