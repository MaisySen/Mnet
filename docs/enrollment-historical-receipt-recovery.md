# Actual Store historical receipt recovery, inactive

Private registrarHistoricalReceipt accepts the full independently pinned original Challenge and the presaved canonical nonzero native secret. It does not accept a response-selected node, receipt, claim or public digest as an authentication shortcut. There is no route, transport scheme registration, startup caller, native State write or authority producer.

The actual retained Store owner and mutex guard the complete read. Closed/frozen/released ownership refuses. Strict populated v2 registrar namespace, exact permanent claim, exact consumed-proof index, immutable full challenge, transcript digest and receipt bytes must pass. Canonical raw device key converts to the existing standard-base64 claim identity, never an alternate guessed node. Constant-time comparison hashes the canonical secret TEXT with SHA256, matching original own-PKCE and current native credential semantics. Public credential digest is not a password. Wrong secret, changed tuple/nonce/key/expiry and missing history all refuse with no success data. A refusal must never be interpreted as permission to create a new attempt or evidence that a remote commit was absent.

Output is ONLY detached historical ReceiptV2 DATA plus its original digest. It contains no current, enrolled, approved or active flag, no bearer secret, routes, map or relay. Receipt is reconstructed using the existing shared canonical recipe and must match the actual retained digest. No ID, node, IP, expiry, proof or credential is generated. Reads never save, advance map version, notify, renew, repair, allocate or revive. The actual current-credential/map/endpoints methods remain separately responsible for current authority and still deny expired/revoked/deleted identities.

Original receipt survives actual ExpireNode/DeleteNode and owning Close/reopen, including the absent-node tombstone. An expired but valid historical record remains readable from this recovery path. That is intentional, not a missing current-expiry check: a lost commit response still needs exact historical reconciliation after access ends. No access-expiry or re-enrollment policy is selected here. The presaved secret remains a historical-lookup secret even when it is no longer a current network credential; future external ingress must preserve this narrow scope and disclosure policy, not label returned history as successful current enrollment.

Evidence uses actual existing test-only strict consumed-history fixtures and real Store lifecycle/persistence, never a new fake transaction or permit constructor. Tests cover immutable bytes/no memory-disk-map-version change, repeated detached values, actual live/expired/Expire/Delete/reopen, every scalar full challenge/binding field changed, wrong/public-digest/zero secrets, missing namespace, mixed legacy token/approval identity, transcript/receipt/index corruption, foreign node key, routes, legacy v1 and owner loss. Eight simultaneous readers race actual Expire/Delete/Close. Full temp/create/write/short/sync/close/rename/postrename/dirsync failures on actual DeleteNode show rollback-safe retained history, uncertainty freeze before reopen, and exact whole-image active or tombstone receipt after owning reopen. The history reader performs no filesystem write and cannot repair an uncertain owner.

Targeted race five times, affected control/controlclient/daemon/pending/contract race, full graph and full vet pass. Initial new test compile used the wrong existing ApprovalIdentity type name and then nil map initialization, corrected before final passing evidence. The fixtures establish no authenticated source/proof producer and no actual first commit.

Limitations remain: full O(history) validation per request has no new cost bound and MUST NOT be exposed as production ingress before its independent bounds review. This solves an internal existing-history recovery seam, not exact-origin authenticated delivery, lost-bootstrap challenge/response recovery, receipt-to-native installation/finalization, atomic source proof to first receipt commit, source time/access-lease/revocation policy, installed version floor, D1 or physical/native acceptance. No pending secret/credential is disclosed externally; no deployment or activation is made.
