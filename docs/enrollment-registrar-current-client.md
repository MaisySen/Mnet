# Dedicated inactive registrar current-control client

New RegistrarClient in internal/controlclient is separate from legacy Client. Existing legacy methods, daemon startup/rejoin and native State schema stay unchanged. No production caller, file loader, server handler/route, enrollment transaction or installer consumes this client. Syntax-consistent NativeCredentialDocument is caller DATA, never proof of receipt provenance, installed policy or authority. No bootstrap client is reused for current network access.

## Explicit experimental current-control proposal

Verified exact HTTPS origin must equal receipt/challenge RegistrarOrigin. Proposed fixed POST paths are /api/mnet-node-experimental-v1/map and /api/mnet-node-experimental-v1/endpoints. These paths are not registered or deployed. Authorization is Mnet-Node-Credential-V1 plus one space plus canonical native secret, separate from bootstrap and legacy X-Node-Token. It is bearer-on-wire inside verified HTTPS, not a challenge response or proof of current consent. Request JSON has exact version1, full qualified receipt-v2, receipt_digest and endpoints. Map request endpoints is null; endpoint request is an explicit array, including empty array for clearing. Secret is never in body/query/URL/legacy headers. No route accepts this envelope in this checkpoint.

Constructor checks full new document consistency and actual commit/access interval, then copies it privately. It does not read native owner/journal/current policy, authenticate document provenance, generate a credential, contact source/registrar, consume a proof or finalize State. Caller cannot change copied receipt/scope by mutating original struct. Origin comes from independently supplied matching document, never a response. Bounds are explicit timeout<=1min,1..4 concurrent requests, finite maxRequests up to256 and at least concurrency. These are engineering client bounds, not chosen product admission/lease policy.

CurrentMap accepts exact envelope version1/receipt_digest/map. Parsed map must name SAME node/network/public key and exact access expiry, approved, no self routes/exit/account-user capabilities. RelayURL must be empty: a returned map may not choose a new token destination, and no legacy credential-bearing relay URL can be used. Peers capped4096. Map version nonnegative. This does not validate every peer endpoint/route against a separate policy or guarantee packet delivery. Remote exact registrar remains map authority; client checks own credential epoch consistency. A snapshot after this point is DATA, not a continuous access lease.

Endpoint reports accept max64 canonical numeric address:port values, nonzero ports, no zones/mapped IPv6/hostnames/noncanonical text. This intentionally narrows the disconnected client subset without changing legacy Store endpoint semantics. Response must be version1/SAME receipt digest/updated:true. Network/protocol/status failure is outcome-unknown and never auto-retries; an admitted request always spends budget. The future actual owner must reconcile any update rather than infer absent side effect from a lost acknowledgement.

HTTP401/403 permanently retires this owner and all copies, cancels concurrent work and drops its reachable document. ErrRegistrarDenied deliberately differs from legacy ErrUnauthorized and must never trigger legacy Join/rejoin/credential replacement. No rejoin method exists on RegistrarClient. Other failures do not refund budget or retry automatically. Constructor reconstruction can reset lifetime budget, so native durable history/policy and ingress bounds must be separate before activation.

## Transport, grammar and lifecycle

Owned fresh transport, verified certificates/hostname, TLS1.2 minimum, HTTP1.1 only, no cookies/environment proxy/DefaultClient/DefaultTransport/caller transport or TLS injection API, redirects, connection reuse or request body rewind. No response can select another destination. Explicit no-store request and response; one JSON Content-Type, no encoding, header16KiB/body4MiB caps. Errors do not include upstream body, URL, Location or raw transport cause. No request payload logging.

Response grammar checks exact field names at every depth, duplicate/unknown/case-alias/null required envelope/scalar refusal, literal int64 integers, UTF8/depth/array bounds, and valid RFC3339 timestamps. Legacy netmap nullable slices and optional pointers are preserved, but nil current self expiry/null map refuse semantic validation. Optional omitempty fields may be absent. JSON whitespace and surrogate-to-replacement semantics remain; never authenticate bytes reconstructed from parsed structs.

Client copies share mutex/admission counters/lifetime. Access expiry installs actual deadline cancelling in-flight requests. Close marks owner closed, cancels I/O, closes idle transport and replaces its reachable private document with empty value. It does not wait for remote handler completion, undo updates or promise memory zeroization. Local request/JSON/Go string copies can retain secret until collected; this is inactive fixture-only storage, not safe live credential provisioning. Before future activation, native retained owner/current policy, usable State schema, secure secret ownership, authenticated receipt provenance and continuous packet/relay lifecycle need separate review.

## Evidence and limits

Local verified TLS fixtures inspect exact dedicated path/header/body, no legacy/ambient/cookie inheritance, SAME full receipt scope, current map and endpoint ack, request budget/no refund,12 copied concurrent callers blocked at concurrency cap, Close cancellation, actual access deadline, TLS-untrusted/redirect sink zero hit, wrong node/network/key/receipt/expiry/approval/self routes/relay refusal, malformed nested duplicate/case/unknown/missing/fraction/null/size/cache/encoding/status and wrong ack/purpose. Denied copied owner never resends and is never legacy ErrUnauthorized. Formatting redacts secret. Grammar fuzz seeded with typed map plus malformed input. No actual owning Store handler or end-to-end network enrollment/current map delivery is claimed. Independent actual Store same-lock operations remain a separate prerequisite, not automatically connected by matching filenames or envelope names.
